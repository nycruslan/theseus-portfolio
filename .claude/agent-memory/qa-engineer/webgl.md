# The 3D and WebGL lessons (from MEMORY.md, sprint 48)

- CI's headless Chromium draws WebGL in SwiftShader and refuses `failIfMajorPerformanceCaveat`, so specs need an init script; read WebGL pixels from screenshots, never `readPixels`. The harness (`e2e/webgl.ts`, `e2e/pixels.ts`, `openRun` ordering the init scripts with the recorder last) retired with the hero in sprint 22: take it from git history for B3's 3D (sprints 9, 10 and 22).
- At 4x CPU on SwiftShader the renderer's CDP traffic lags 0.7 to 1.25 s (a binding's call reached Node that late), so neither a polled `waitFor` nor a bound press lands inside a 2.4 s move: report where an input landed, read in its own capture `keydown`, never gate on it. Event Timing skips untrusted events, so an init script can't fake an INP sample (.crew/sprint/25/).
- Specs at 4x CPU share the machine with the other worker: B3.9 alone reached frame 1 at about 1.5 s, beside B3.6 at 2.2 to 2.9 s, so its long-task and INP numbers are floors of floors (.crew/sprint/25/).
- On `/` at 1024 px and up, `[data-model]`'s `data-state` restyles the drawing (call 5's hollow rule: no fills, numbers or leaders from the first lofting frame), so a non-B3 spec that reads the drawing's paint, numbers or leaders opens it with `refuseWebGl`, or it races the idle import (.crew/sprint/25/).
- requestAnimationFrame's timestamp is the vsync-aligned frame start: under a 40 ms spin it steps 33.4 and 50 ms while the callbacks run 40 apart, so a "frames at least X ms apart" check reads performance.now() in the callback, and the page's own interval rules see the stepped timestamps (.crew/sprint/26/).
- Chromium lays out in 1/64 CSS px, so at a non-integer ratio (1.5) a whole buffer's CSS size can't be exact (320 rows ask 213.333, get 213.328): compare buffer and CSS × ratio to ratio/64, never 1e-3 (.crew/sprint/26/).
- A touch drag through CDP `Input.dispatchTouchEvent` scrolls the page, but a release in motion flings on (150 px dragged, 395 scrolled) and Chromium's 15 px slop goes unscrolled: hold the finger still 300 ms before touchEnd (`touchDrag` in e2e/model.ts) and assert the scroll within 16 px of the drag (.crew/sprint/26/).
- In real time beside other workers a replayed loft can end `still` (sprint 26's stepping on a slow frame), so real-time checks accept any rest state and only clock runs ask for `settled` after the duration; a `page.mouse.click` at a button's centre presses with the clock paused (.crew/sprint/27/).
- A hover hook (`data-pick`) is found by pointermove events dispatched in-page at `elementFromPoint` and read after each (1 s for 4,361 cells), then each chosen point hovered with the real mouse: a real-mouse scan of the same grid took 90 to 110 s, and the dispatched one matched it cell for cell (.crew/sprint/33/, decision 12, e2e/ghost.ts scanSeats).
- A scan or settle is the slow part of a WebGL check: scan once per size and switch the scheme in the same context (a geometry read doesn't change with it); B5.19 with a scan per scheme took 11 minutes on one worker (.crew/sprint/33/).
- On SwiftShader the scene build delays transitionend by 400 ms and more past a 240 ms fade: read a transition's end from its own declared timing (`getAnimations()` at transitionrun, `getComputedTiming().endTime`), not from event times (.crew/sprint/33/).
- `run.scripts()` in e2e/webgl.ts keeps every script response since the page opened, across gotos: a "this page fetches nothing more" check slices the list at its own goto, or `/`'s idle chunk counts against `/log` (.crew/sprint/33/, Forge's trace).
- On Playwright's clock a whole 3D move is every frame (~110 on SwiftShader at 1440, 10 s and more), where real time ends it `still` after 6: step the clock only through the frames a check measures, and reach rest by Calm or an input otherwise (.crew/sprint/33/).
- On `/` there is no seat pick, so a 3D seat is located two ways: at frame 1 the model lies on the drawing, so the 2D plank's fill is its projection; at rest, the pixels that differ from the default server's at the same pose give the changed seat's box (B4.21, .crew/sprint/34/).
- Three's fat lines count 6 triangles a segment in the harness's counter: B4b's copper tip added 18 (3 segments) at 1440 and 390, so "plus the tip's segments" is a small, exact allowance (.crew/sprint/34/).
- Hiding `body *` to isolate a drawing also hides its `<clipPath>` children, and SVG drops invisible clip geometry, so every clipped plank paints nothing (B4.36's first silhouette was empty): keep `svg clipPath *` visible, and read a hull's silhouette as its outline filled with its own stroke, B3.1's method (.crew/sprint/36/).
