# /crew: the feed, the panel, the poll and the replay

Moved here from MEMORY.md in sprint 47, when it reached its 25 KB load limit. One line each, with
the reason.

- A module-level `let` assigned inside a top-level `"use cache"` function isn't captured into the cache key, and it survives from one regeneration to the next in a `next start` process (lib/crew-feed.ts's `kept`, proven over Probe's fixture feed); Next's docs say the default in-memory cache doesn't persist across serverless instances, so on Vercel such state lasts only as long as a warm instance (`.crew/sprint/31/`, the owner's feed comment on #78).
- Probe's `e2e/crew-feed.ts` harness runs outside Playwright: a scratch `.mjs` imports it by absolute path under `node --experimental-strip-types` with the checkout as cwd (it copies that `.next`); /crew reads the feed at most every 30 s, so a channel switch shows once `feed.reads()` rises, plus about 5 s for the regenerated page (`.crew/sprint/31/`).
- `next dev` refuses a symlinked `node_modules` too ("Could not find the Next.js package"), so a second server beside a running e2e suite must be `next start` on a copied `.next` (e2e/crew-feed.ts's `startSite`), not a linked dev copy (`.crew/sprint/34/`).
- e2e/crew-feed.ts's `set(channel, answer)` merges into the channel's last answer and JSON drops `undefined`, so a switch that must clear a `patch` or `raw` sends `null` for it (`.crew/sprint/34/`).
- A copper dot drawn as a border reads as a disc only at an even size with a border of half of it (8 px, 4 px); 7 px with 3.5 px renders as a ring (Iris, `.crew/sprint/34/notes-iris.md`, 5).
- Under `cacheComponents` and `partialPrefetching`, a page that awaits a `"use cache"` read whose `stale` is under 5 minutes (lib/crew-feed.ts's 30 s) outside `<Suspense>` makes dev's instant-navigation validation log "encountered URL data during prerendering or a navigation" at the await: such a read is in the prerender but not the App Shell (cacheLife.md, "Prerendering behavior"). The build prerenders the page whole (`○ 30s 5m`), and the site has no `next/link`, so no navigation uses the shell; `/` and `/crew` both log it, feed URL set or not (`.crew/sprint/34/`).
- /crew's panel (components/crew.tsx) renders on the server and again in the browser, reaching the browser through the `"use client"` components/crew-live.tsx, so it and lib/crew-run.ts import nothing server-only (`next/cache`, content/profile.ts): the owner's name and the retros' facts come in as props. Its link classes live in components/crew-link.ts since sprint 48 (Lens's nit on #110), which the server-only keel and `/`'s key import too, so nothing server-side imports the panel (`.crew/sprint/48/`). It is `"use no memo"` since sprint 37: the compiler's caches on it (58, 33 and 26 slots) cost 3,049 B of a 21,277 B chunk, and it re-renders only on a poll or a replay's step. The page's whole client code (poller, panel, replay, model loader) is one chunk, the only file beyond the 404's: 18,508 B at fb5274d, 18,820 B after sprint 48's Approval link (+216 B) (call 8's budget 20,480); measure it on the final head's own build (`grep -l data-replay-pause .next/static/chunks/*.js`), since a reviewer's late JSX moved it 280 B after a figure had been reported (`.crew/sprint/35/`, `.crew/sprint/37/`).
- A MutationObserver an init script attaches to `document` records the HTML parser's own insertions, so a "hydration changes nothing" check sees hundreds of childList records; attach it to the panel once its last child is parsed (a document observer that waits for it), and only script mutations remain (`.crew/sprint/35/`).
- /crew's detail is server HTML that React hydrates but never renders again, since `CrewPlan` is a server component that takes no client state: that is why the poll and the replay may write to it (components/crew-live.tsx `redraw`), and why a client render of it would undo their writes (Lens's nit on #91). Every write is guarded (an attribute set only where it differs, `classList.toggle(name, force)`, `textContent` compared first), so an unchanged answer makes 0 MutationObserver records (`setAttribute` with the same value still queues one), and a new tick is cloned from the server's slot paths in `data-slots`, so the client carries no geometry (`.crew/sprint/36/`).
- `position: sticky` always makes a stacking context, so a drawing's `z-index: 1` lettering inside a sticky box paints under the model's canvas layer beside it: /crew wraps the drawing and `[data-model]` in one sticky `.crew-drawing` (Pixel's finding, `.crew/sprint/36/`).
- Under `page.clock`, `runFor` fires a poll's timer but the fetch resolves in real time, so a read right after `runFor` sees the previous answer; wait in real time (`page.waitForTimeout(400)`) before reading. A 30 s abort timer will also fire on a 30 s jump if the page hasn't processed an answer the route already fulfilled (`.crew/sprint/36/`).
- A step timer that a React effect re-arms after each render advances one step per `page.clock.runFor`, however long, since React renders on a MessageChannel the fake clock doesn't run; a clock that arms its next step inside the timer's own callback lets one `runFor(n × step)` run all n (components/crew-live.tsx `transport`, `.crew/sprint/37/`).
- State an effect sets up once per page (/crew's replay clock, a `#replay` read from the address and then dropped) lives in refs, not effect locals: Strict Mode's development re-run runs cleanup and the effect again with refs and state kept, so a local transport restarts empty while `replay` state still lists the first run's, and a hash dropped by the first run is gone for the second (components/crew-live.tsx, `.crew/sprint/40/`).
