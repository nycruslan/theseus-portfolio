- Size a three.js canvas in whole drawing-buffer pixels (`round(css × dpr) / dpr`). three floors the buffer but rounds the viewport, and a fractional height lifted the registered hull 0.4 px at DPR 2 (`.crew/sprint/24/spike/spike.md`, S4).
- `BatchedMesh` is one draw only on WebGL with `WEBGL_multi_draw`. WebGPU, and WebGL without the extension, draw once per instance: 26 draws for the hull. One merged plank mesh with a per-vertex plank index keeps every stack within 8 (`.crew/sprint/24/spike/spike.md`, S3).
- `LineSegments2.onBeforeRender` resets `LineMaterial.resolution` to the renderer's viewport on every draw, so a renderer driven at pixel ratio 1 in whole buffer pixels needs the line widths × the buffer's ratio, or DPR 2 draws them at half weight: it showed as a one-device-row registration offset at DPR 2 only (`.crew/sprint/25/`, `lib/model/stage.ts`).
- A dolly-zoom from orthographic doesn't fit a PerspectiveCamera at D = lens/e: the first frames put 10^6 px of translation through float32 and coplanar seams fight the card for depth. Hand-set an OrthographicCamera's projection at the origin instead, `[2/W,0,0,−1; 0,2/H,0,1; 0,0,−1/zHi,zHi/D; 0,0,−1/D,1]`, which is the canvas at z = 0 for every D (`.crew/sprint/25/`, `lib/model/stage.ts`).
- Headless Chromium reads a WebGL canvas back for software compositing ("GPU stall due to ReadPixels"), so in the 4-vCPU cloud each frame is a 100 to 300 ms main-thread task: a real-time loft trips the 33.4 ms net after six frames and a test's state polls starve between frames. Hold states with Playwright's clock, and measure feel only on a GPU (`.crew/sprint/25/`, B3.9).
