## Measuring and reviewing

- Measure fits in the browser CI runs: the revision `@playwright/test` pins (1.64.0 → headless shell 1248, Chromium 156; check `--version`), launched through `@playwright/test`. My Wb call came from a stray `playwright` package on shell 1243 (153) checked against Chrome 153, the same engine twice, and Forge found 393 × 659 10 px out in CI (sprint 44).
- To review a PR's build without its preview: `git archive <sha>` into the scratchpad, `pnpm install --prefer-offline`, `node node_modules/next/dist/bin/next build`, then `next start` with `CREW_FEED_URL` on a small server serving `e2e/fixtures/crew/live.json` with fresh times and `current.sprint` 999, and poll until "drawing now" appears (sprint 43 review). Drive it with that copy's own `@playwright/test` (`createRequire` on its `package.json`), so the browser is the one CI pins (sprint 44 review).
- To prove a phone-only sprint left everything else alone, pixel-diff the first window of a base build and the head built the same way, both with no feed and WebGL refused, fonts warm. Production's live feed changes the revisions and makes that diff noisy. Sprint 44 read 0 px at 1440 × 900, 1536 × 715, 1024 × 768 and 768 × 1024, and on /crew, /log and /read at phones (`scratchpad/iris/desk.mjs`).
- Playwright's headless shell sets glyphs at whole-pixel advances, which shows in screenshots as uneven letterspacing ("JPMorg an", "res earch"). Judge type and texture in Chrome, and fits in the shell CI runs (sprint 44 review).
- Commit from another role's worktree without touching its checkout: `GIT_INDEX_FILE=<scratch> git read-tree <base>`, `git hash-object -w`, `git update-index --cacheinfo`, `git write-tree`, `git commit-tree -p <base>`, then `git branch` and push (sprint 44 review).
- impeccable's URL detector needs `IMPECCABLE_BROWSER` pointed at a Chromium wrapper that adds `--no-sandbox` when the session runs as root; axe needs `browser.newContext()`, not `browser.newPage()` (sprint 4).
- Judge motion from frames at Playwright's clock times and a reduce fade by pausing and seeking its transitions; SwiftShader's colours are exact, so colour calls hold on them and only feel waits for a GPU; a full-page screenshot fires a resize on the page (`.crew/sprint/25/notes-iris.md`, `review-iris.md`).
- Shoot a loft in frames on Playwright's clock, not real time: SwiftShader takes about 3 s a screenshot at 1440, so real-time capture got only frame 1 and rest. `clock.install()` before `goto`, `pauseAt` the page's own `Date.now()` plus a little (node's clock is behind, and it throws), `runFor` to each time. CSS transitions don't follow that clock (sprint 34, `review-iris.md`).
- The crew feed's fixture harness runs outside Playwright from a scratch copy of `e2e/crew-feed.ts`: since sprint 34's checks it exports only `crewTest`, so drop the `@playwright/test` import, export `startFeed` and `startSite`, and run a `.mts` script from the worktree's root: `startSite(feed.set(channel, { fixture, patch }), feed.ca)` per state, `startSite(null)` for down, `untilHome` before reading `/`; a `patch: { current: { sprint: 999 } }` puts the pencil on the next real seat. The sites take OS-free ports and symlink the worktree, so stop them (by the script's PID) before switching branches (sprint 34).
- Review `/crew` states without the e2e harness: a plain http server serving `e2e/fixtures/crew/*.json` with a fresh `asOf`, `CREW_FEED_URL` pointed at it, and a 31 s wait after each switch for `readCrew`'s cache; the first request after start serves the build's page, so reload once (`.crew/sprint/36/review-iris.md`).

## Prototyping

- Prototype a table or header change in minutes by injecting the contract's markup and CSS into production's page with Playwright: real strings, fonts and both schemes at every width, before Forge builds (`.crew/sprint/32/notes-iris.md`).
- Prototype a 3D call over the real page: tsc `lib/` (drawing and `lib/model/*`) to JS, export `draw` in the copy, serve it and three's files from a CORS static server that rewrites `"three"`, `'three'`, `three/addons/` and `@/lib/` (three's addons use single quotes), inject a module into production with Playwright `bypassCSP`, and drive the real `createStage` with a stand-in loft `{ at(e) → { pose, invD }, lens, scale }` (sprint 36; `.crew/screenshots/36-iris/proto.js`, `serve.mjs`, `shoot.mjs`, which git ignores).
- To try a plank state on production's own hull, wrap `uniform4fv` and change the 92-float `uStates` upload (slot = the plank's index in PLANKS; alpha below 0.75 is the hatch) (sprint 34).
- To show the 3D in a state the feed isn't in (the pencil on 5.0), patch attributes only, after load, then click Off and Full to remount the model. A patch at DOMContentLoaded that also moved a node didn't survive to the model's read, most likely because hydration re-rendered the drawing (sprint 43).
- Canvas mocks use real renders: the model rendered with three.js from `lib/half-model.ts`'s geometry, every artboard checked with axe in a stub before publishing. Sources and recipe: `.crew/sprint/17/render/` (sprint 17).
- Prototype a social card in minutes by importing next's compiled `next/dist/compiled/@vercel/og/index.node.js` in a node script with the vendored TTFs; it reproduced the build's PNG byte for byte (`.crew/sprint/41/review-iris.md`, must 1).
- A height-driven fit inserted as CSS custom properties: a percentage inside a custom property resolves where it's used, so put width-derived offsets in margins (which read the width), never `top` (which reads the height); a conditional step can be written as `clamp(0px, (a - b) * 1000, step)` (sprint 44, `.crew/sprint/44/placement.md`).
