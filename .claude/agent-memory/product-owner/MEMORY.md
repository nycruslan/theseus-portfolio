- The redesign milestone (`ROADMAP.md`) builds sprint 17's approved direction as B1 to B5; its budgets and build order are in `.crew/sprint/17/direction-iris.md`. B1 replaces today's page, so its contract sorts the live specs into keep, rewrite with the same assertions, and retire for the owner to approve, all in that one PR (sprint 15's finding: a redesign meets the guards in clusters).
- Read the existing specs before writing a contract: say which live checks already cover the intent, and place new requirements so they stay green unedited. Probe can't weaken a test and builders can't edit `e2e/`, so a contract that collides with a live guard stalls the sprint (sprint 2).
- Almost every guard loads `/` only, so a contract for a new route re-runs axe, the colour tokens, 24 px targets, overflow and the keyboard on that route (sprint 12).
- Check the code before trusting the roadmap's boxes or a follow-up list: both go stale after a big PR (sprints 3 and 11).
- A direction's own numbers can contradict each other, so cross-check them. Work that rests on an unrun spike gets the spike first, and every number in its contract cites a measurement (sprints 7, 9 and 15).
- CI's Chromium draws WebGL in software, so WebGL checks need init-script control; split such an item into a static part and an upgrade part (sprint 7).
- Name tokens in a contract by their fixed custom-property names, so Probe's checks are deterministic (sprint 1).
- Test a data-driven object against the viewport's crop: an order that puts the newest plank last can hide it on a phone (sprint 15).
- Retro fields turn public when the PR merges, and `outcome` is written before that: a feature that publishes team-written text is an owner decision, and `outcome` is never shown as status (sprint 12).
- An "axe pass" contract targets what axe can't see (keyboard order, the skip link, forced colors), since axe was already clean (sprint 4).
- A redesign's first sprint leaves out controls and links whose targets don't exist yet: a control that changes nothing, or a link into a 404, costs the visitor (sprint 22, `.crew/sprint/22/contract.md`).
- Fixed Tab bounds in specs (`keyboard.spec.ts`'s `tabUntil` of 12) cap how many links a new header can add, so count the stops in the contract (sprint 22).
- Retros hold no dates, so anything dated needs the sprint skill (an owner path) or GitHub (sprint 22).
- A budget no spec measures goes unenforced: B1's script-bytes budget had no check until B2.10, so give every budget a named check or mark it reported (`.crew/sprint/23/contract.md`).
- Guards read source as well as pages: B1.10 wants each next/font import exactly once in `app/`, so a second route on the display face shares one declaration (`.crew/sprint/23/contract.md`).
- Specs that select by structure (`section li`, its `h3`, one link) survive a card-to-row redesign when the contract states those hooks as data rules; only the tests about the old object retire (1 of 93 in `.crew/sprint/23/contract.md`).
- Once the 3D exists, the approved canvas makes Full the default and starts reduced motion at Calm (`Motion-Control.html`). B1's "Off for everyone" held only while there was no 3D, so check every live guard against the default mode, not the Off frame (`.crew/sprint/24/b3-plan.md`).

- Put an owner call that can reverse a stack in the first build PR that waits for the owner anyway, with the real thing on its preview, not at the milestone's end, where reversing it means redoing that PR's work (`.crew/sprint/24/b3-plan.md`).
