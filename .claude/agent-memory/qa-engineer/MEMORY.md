- Guard blocks a Bash line that both writes files and runs a script it can't read, and `kill $(...)`: Write the script in its own step, note `$!` when starting a server, then `kill <pid>`; `pnpm start` leaves a child chain (pnpm, sh, pnpm exe, next-server), `pgrep -P` two levels misses the last one, so find the `next-server` by its start time/port and kill each pid, never by name or port (see `.studio/sprint/1/verify-probe-2.md`). The guard also refuses a line that builds a path from a variable and mentions the team folder; use literal paths (copy a scratch app with `cp -a app components content e2e ... node_modules <literal scratchpad dir>/`).
- Iterating fast: serve a build yourself and run `PLAYWRIGHT_BASE_URL=http://localhost:<port> pnpm exec playwright test e2e/<file>` (skips the config's build); final runs use `PLAYWRIGHT_PORT=<free> pnpm test:e2e`.

- Facts learned in sprint 2: Tailwind preflight makes a bare `<input>` background transparent, use `background-color: revert` or `Canvas` to observe `color-scheme`. `page.evaluate` works with `javaScriptEnabled: false` (page scripts are off; `self.__next_f` is undefined proves it). Next puts viewport/meta elements and the 404 boundary CSS in `self.__next_f.push(...)` flight scripts, so a whole-HTML "no script mentions X" check fails on framework text. Local `main` can lag; use `origin/main`.
