# The Log's lessons (from MEMORY.md, sprint 53)

- A rule that waits on a record written after the merge (merge.json) meets its own PR's CI with the newest sprint unrecorded: walk each order rule and "newest" sample through that state before writing (Undated last would have put 32 under revision 1; B5.15's newest became the newest with a record) (.crew/sprint/32/decisions.md, 9).
- Grouping a table's tbody adds header rows, so every spec's `tbody tr` selector counts them: the Log's revision rows are `tbody tr:has(> th[scope="row"])`, in log.ts, log-entry.spec.ts and sheet.spec.ts (.crew/sprint/32/).
- Below 768 px on the Log the bar's Read as page and control slot are hidden and one row (`main > [data-foot]`, `.log-head`'s next element in the DOM; since Ya, sprint 53, set under the h1 and above the drawings, Iris's addendum) holds Read as page then the control, so the bar's target list is the header's shown targets then the row's, the same list at every width; Tab from Contact goes Read as page, then Off with WebGL refused (.crew/sprint/31/, the merge with #83).
- B5.6's hand-written plank anchors (sprints 1, 13, 24 in e2e/log-record.spec.ts) gain "Sprint N has since replaced it." whenever a merge retakes their seat, 22 merged retros on (36 took 13's 6.1, 46 took 24's 5.1): at each close, run `seatHolders` from lib/lines-plan.ts on the merged list and grep e2e/ for the next seat's holders before CI finds it (sprint 46).
- Every step's server HTML is read in seconds: `request.get(url)`, then `page.setContent(html)` in a scripts-off context with `page.route('**/*', abort)`, and the same in-page reader as a real page; it answers structure and words, never paint, so a check needing paint loads the contract's sample pages (e2e/log-yard.spec.ts serverYards: 52 pages, Y1 6 s, sprint 53).
- The yard's oracle is e2e/retros.ts (STEPS, THESEUS_AT, GHOST_AT, COUNT_AT, QUESTION_STEP, from the contract's rule), its words YARD_WORDS in e2e/log.ts (Iris's, one line each), and `ghostOn(url)` in e2e/ghost.ts the ghost a page draws: a check on a record's ghost reads ghostOn, never GHOST, since a step's ghost has gaps before its 22nd merge (B5.18, B5.19 since sprint 53).
- A contract's "measured room" can miss a kept first-screen clause at another size: Ya's measured 390 x 844 and 1440 x 900, but B5.25 holds Full, Calm and Off inside 320 x 568, with 29 px of room on main, and the bare mutant found it; list every kept clause's viewport (B5.25 320 x 568, B5.18's fits, B5.1) before the placement call (sprint 53).
- Build the contract mutant to the designer's DOM order once it lands, and rerun the order-sensitive specs (Tab walks, the phone row, the record's links): Iris's addendum moved the phone row and Start again, which turned B5.1's row clause red where the first bare mutant was green (sprint 53, mutant2).
- A card check reads what a preview reads: each step's server HTML (request, then setContent with scripts off) and the image by its tag's pathname plus search (the `?hash` is part of it), compared by sha256 of the bytes, never pixels; it reads all 52 steps and their cards in about 8 s (e2e/log-cards.spec.ts, sprint 54).
- In Next 16 a dynamic segment's opengraph-image takes `params`, but a static `alt` export is one alt for every step: a per-step og:image:alt needs `generateImageMetadata`, which moves the URL to `/log/n/opengraph-image/<id>` and prerenders it (● at build, ƒ before); so Y9 checks the path is under `/log/n/`, never an exact one (sprint 54's mutant).
- A contract mutant's card in app/ takes its colours from lib/site.ts's LIGHT: invariants.spec.ts's "no color literal" scan reads app/ and turned sprint 54's whole-suite mutant run red on one `#fff`, its only red of 361 (39 minutes on 2 workers here: start it in the background as soon as the mutant builds).
- Helpers that find a plank by the canvas's middle row or scan the whole canvas (`aPlank`, `twoPlanks`, `scanSeats`, B5.19's `plankCells` histogram over `canvasBox`) assume the canvas is the ghost's box: once the Theseus shares it (Yc), the middle row is its caption and the opaque card takes the coverage histogram. Read them over `[data-ghost]`'s box (sprint 55's mutant: B5.19, B5.20, B5.23 red on it alone).
- A riffle (Yd) is read on Playwright's clock by a MutationObserver on `[data-model]`'s data-press with attributeOldValue: each value set is a step's start, each removal a landing, and the step before a stop lands in the task the stop starts, so the stop's own landing is the first removal after its start (Y23's first draft read the earlier one); the timing is exact whether the controller paces by timers or frames (e2e/log-riffle.spec.ts recordRiffle, .crew/sprint/56/).
- Build a contract mutant's bare handler to the designer's calls for what already exists, or its own bugs read as kept reds: sprint 56's first hold landed every quick press on release (Y13 to Y17 red) and put the hand-off in Next's slot, which Iris had ruled out (Y7's overflow); read the calls file before the 30-minute kept run (.crew/sprint/56/decisions.md, 7).
- Holds: Playwright's keyboard.down on a key already down sends it again with repeat true (an OS autorepeat), a CDP touchStart held still fired no contextmenu in headless Chromium (dispatch one to test a cancel), and Chromium reports layout shifts made while a pointer is held at the release with hadRecentInput true, so a hold's CLS is read after the release (Iris's measure, .crew/sprint/56/riffle-iris.md).
- On /log the yard never mounts (lib/model/yard.ts plays /log/n only), so `[data-model][data-yard]` never appears there: a Full read on /log waits for rest, never for data-yard (sprint 59's first H1 draft spent its 20 s timeout per window on it).
- A Full load at 390 takes about 2.2 s to `document.fonts.ready` (the chunk compiles alongside), WebGL refused 0.9 s, scripts off a few hundred ms: budget a Log spec by each load's mode, and sweep every step's layout scripts off (57 steps at 390 x 844 in about 7 s, H5 in e2e/log-hand.spec.ts, sprint 59).
