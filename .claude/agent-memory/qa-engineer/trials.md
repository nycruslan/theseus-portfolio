# The trials page's lessons (from MEMORY.md, sprint 70)

- Chromium gives `pointermove` no Event Timing entry (a 4x CPU drag on a mock logged pointerdown, up, over and the captures, never move), so the moves show only as `long-animation-frame` entries. On the trials page those are the framed /'s relayout (200 to 380 ms at 4x on a loaded box), so Atlas ruled T14 gates Event Timing and only reports the frames; don't propose a frame gate for a framed reflow (.crew/sprint/64/).
- Steer a drag whose pointer-to-size mapping the build decides by feeding back on what the page reports (dragTo in e2e/trials-drag.spec.ts: measured gain, moves clamped), and prove the mechanics before the build on a scratchpad mock controller built to the selectors file: it caught three reads that ran before a late settle (.crew/sprint/64/).
- An input or key rule that steps the grid on a 1 px edit skips the off-grid swept windows beside the shown one (1439 x 900 from /trials is in H10's run): T12 types 1439 there, since grid-only clauses (1024, 640) passed while the bug shipped (Lens on sprint 64's e4eeb33).
- Chromium's touch adjustment moves a CDP touch tap (page.touchscreen.tap, isMobile on or off) onto a link within about 8 px when nothing tappable is under the point: a tap at 1024x640's point on the trials chart at 390 clicked the 1160x635 sounding, while the mouse at that point hit the plot. Test a tap-the-plot rule by touch as well as by mouse; the fix makes the plot itself a tap target (.crew/sprint/65/).
- Map SVG geometry across nested svg viewports with getScreenCTM, never getCTM, which stops at the nearest viewport: the chart's soundings sat in the outer svg and g[data-plot] in a nested one, so getCTM put them in different spaces (.crew/sprint/65/).
- The trials loader attaches in a useEffect, so under two workers a tap or corner press right after frameReady can come before hydration and do nothing (the reduced-motion drag failed so on a correct build): wait for `__reactProps$` on `main [data-corner]` first, hydrated() in e2e/trials-chart.spec.ts (.crew/sprint/65/).
- A frame sandboxed without allow-scripts logs one console error per executable script in its document ("Blocked script execution", 46 to 48 for /'s tags), none for a JSON-LD data block; Playwright's page.on("console") receives a child frame's, and a trace's snapshotter injects one script per frame that the sandbox refuses too, so a console count on a sandboxed frame runs with trace off (Forge found it). T36 counts on the page and allows the frame's JSON-LD, which T2's main-equals-/ comparison keeps (.crew/sprint/76/).
